# Unity: что делать и куда что ставить

Инструкция для автора проекта. Код пишет Claude, а действия в редакторе Unity делаете вы: открыть сцену, добавить объект, поставить пакет. Порядок действий — в «Журнале шагов» в конце. Журнал пополняется по мере написания кода.

## 1. Как открыть проект

1. Откройте **Unity Hub**.
2. Projects → Add → Add project from disk → выберите папку `Simulator` (в ней лежат `Assets`, `Packages`, `ProjectSettings`).
3. Версия редактора — **6000.6.0f1**. Если её нет: Installs → Install Editor.
4. Первый запуск долгий: Unity строит папку `Library`. Это нормально.

## 2. Окна редактора

| Окно | Что это |
|---|---|
| Project | файлы проекта (папка `Assets`) |
| Hierarchy | объекты открытой сцены |
| Scene | сцена, где расставляют объекты |
| Game | то, что увидит игрок |
| Inspector | свойства выбранного объекта или файла |
| Console | сообщения и ошибки: Window → General → Console (Ctrl+Shift+C) |

## 3. Как мы работаем

1. Claude пишет или меняет файлы проекта.
2. Вы переключаетесь в Unity. Он сам подхватывает изменения и компилирует скрипты; пока идёт компиляция, в правом нижнем углу крутится значок.
3. Откройте Console:
   - **красные** сообщения — ошибки: скопируйте текст первой ошибки и пришлите Claude;
   - **жёлтые** — предупреждения, обычно не страшно.
4. Выполните действия из нового шага в «Журнале шагов».
5. Сохраните сцену (Ctrl+S) и проект (File → Save Project).

## 4. Структура папок

Папки, которые уже есть:

| Папка | Что там |
|---|---|
| `Assets/Scenes` | сцены (`SampleScene` из шаблона) |
| `Assets/Settings` | настройки рендера URP и ввода (Input System) |
| `Assets/Welcome` | учебная страница шаблона Unity, позже удалим |
| `Packages` | список подключённых пакетов |
| `ProjectSettings` | настройки проекта |
| `Library`, `Logs`, `UserSettings` | создаёт сам Unity; в git не попадают |
| `Docs` | документы: GDD, генератор GDD, эта инструкция |
| `simdocs` | исходное ТЗ и материалы-референсы |

Наш код и данные — только в `Assets/Geminium`:

| Папка | Что там |
|---|---|
| `Assets/Geminium/Core` | ядро симуляции на чистом C#, работает без графики |
| `Assets/Geminium/Game` | связь ядра с Unity: сцены, отрисовка, интерфейс |
| `Assets/Geminium/Data` | файлы данных: продукты, сырьё, станки, профессии |
| `Assets/Geminium/Tests/EditMode` | автоматические тесты |

В папках `Core`, `Game` и `Tests/EditMode` лежит по файлу с расширением `.asmdef` (Assembly Definition, «определение сборки»). Он превращает папку в отдельную сборку — самостоятельный кусок программы со своими правилами. Например, сборке `Core` запрещено обращаться к движку Unity, и при такой попытке Unity сразу покажет ошибку. Эти файлы трогать не нужно.

## 5. Частые действия

- **Открыть сцену:** в окне Project дважды кликнуть файл сцены (значок Unity).
- **Создать объект:** Hierarchy → правый клик → Create Empty. Переименовать — F2.
- **Добавить скрипт на объект:** выделить объект → Inspector → Add Component → ввести имя скрипта → выбрать его.
- **Заполнить поле-ссылку в компоненте:** перетащить объект из Hierarchy или файл из Project в это поле в Inspector.
- **Установить пакет:** Window → Package Manager → «+» слева сверху → Install package by name… (в некоторых версиях — Add package by name…) → ввести имя пакета из журнала → Install.
- **Запустить игру:** кнопка ▶ (Play) сверху; повторное нажатие останавливает. Пока горит Play, ничего не настраивайте: изменения в режиме Play пропадают после остановки.
- **Запустить тесты:** Window → General → Test Runner → EditMode → Run All.

## 6. Если что-то не так

| Проблема | Что делать |
|---|---|
| Красные ошибки в Console, Play не запускается | прислать Claude текст первой ошибки |
| «The referenced script on this Behaviour is missing» | скрипт переименовали или удалили — сказать Claude |
| Настройки пропали после Play | их меняли в режиме Play — повторить после остановки |
| У имени сцены звёздочка `*` | сцена не сохранена — нажать Ctrl+S |
| Unity долго «думает» после изменений | идёт компиляция или импорт — подождать |

## 7. Git

- Перед коммитом сохраните сцену и проект (Ctrl+S, File → Save Project).
- Папки `Library`, `Logs`, `UserSettings`, `Temp` в git не попадают — так и задумано.
- Картинки и PDF хранятся через Git LFS, он уже установлен.

### Шаг 1 — 01.11.2026: папки и сборки проекта

**Что изменилось.** Появилась папка `Assets/Geminium` с подпапками `Core`, `Game`, `Data`, `Tests/EditMode` (что в каждой — в разделе 4). В ядре один файл `CoreInfo.cs` с номером версии. Плюс первый автоматический тест: он проверяет, что ядро не зависит от движка.

**Что сделать в Unity.**
1. Откройте проект и дождитесь, пока закончится компиляция (значок в правом нижнем углу).
2. Window → General → Test Runner.
3. Вкладка **EditMode** → кнопка **Run All**.

**Как проверить.** В Test Runner появляется тест `Core_DoesNotReferenceUnityEngineOrEditor` с зелёной галочкой, в Console нет красных ошибок. Это ваше первое практическое задание: запустить тест и найти его в дереве (`Geminium.Tests.EditMode` → `CoreArchitectureTests`).

### Шаг 2 — 01.11.2026: игровое время

**Что изменилось.** В ядре появилось игровое время:
- календарь (старт 1 января 2027);
- графики смен;
- часы симуляции (1 тик = 1 игровая минута);
- отложенные события;
- пауза и скорости x1–x8;
- генератор случайных чисел с seed.

Код лежит в `Assets/Geminium/Core` и `Assets/Geminium/Core/Time`. На экране пока ничего не видно: время появится в отладочной сцене (пункт 1.13).

**Что сделать в Unity.** Test Runner → EditMode → Run All.

**Как проверить.** Все 27 тестов зелёные. Практическое задание: откройте файл `Assets/Geminium/Tests/EditMode/TimeTests.cs` и прочитайте тест `OneShift_FiveDayWeek_WorksMondayToFridayFrom8To16`. Поменяйте в нём `At(4, 8)` на `At(4, 7)` и снова запустите тесты: этот тест станет красным, потому что в 07:00 смена ещё не началась. Верните как было — тест снова зелёный.
